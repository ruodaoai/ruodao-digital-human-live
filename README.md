# 数字人直播（digital-human-live）

> 英文文档：[README.en.md](./README.en.md)

传一张照片就能开播，也能把数字人嵌进公司/个人产品页做接待。**v0.9.0 重构了整个工作台**：顶部新增「上传形象 → 选声音 → 备话术 → 开播」四步引导条，右侧超长的"主播设定"拆成主播/画面/动作/推流/接待/引擎六个真实标签页，每个标签内按卡片分组，配置一目了然。**v0.8.0 把数字人升级成可接入若道模型的 Agent**：访客打开接待卡即可打字或语音对话，支持一对多直播、一对一独占接待（其余访客排队等待、接待完自动叫下一位）、一对多轮流接待（挨个回答）；同时修复了预览白板、横图被裁切看不全、启用声音无响应等问题。此前版本已支持卡通形象、口型/动作增强、RTMP/SRT 推流、网页接待组件。

**默认零依赖**：不用显卡、不用 API Key、不用装模型，传图即开播。
**可选本地开源口型**：有 NVIDIA 显卡时可接 Wav2Lip / MuseTalk / LiveTalking。

## 一、功能总览

| 模块 | 能力 |
|---|---|
| 形象 | 真人 / 卡通二次元两种类型；透明底卡通可开“抠图”纯净背景 |
| 舞台 | 1080×1920 竖屏，名字/角标/时钟/字幕/跑马灯/商品位，可作 OBS、直播伴侣浏览器源 |
| 动作 | 呼吸、眨眼、点头、轻摆、说话起伏；真人“稳重”、卡通“活泼”两套动作曲线 |
| 口型 | 音频频谱多段驱动（开口 + 唇形宽度），口型强度可调，嘴部/眼部区域可微调 |
| 语音 | edge-tts（一键安装）/ Windows SAPI 双通道，本机合成并缓存 |
| 话术 | 多句轮播、手动下一句、逐句字幕 |
| 推流 | 一键 ffmpeg 推到抖音/快手/视频号/B站/YouTube/自定义 RTMP·SRT |
| 网页直播 | 舞台地址直接作浏览器源（零额外依赖） |
| 接待 | 可嵌入产品页的右下角**数字人接待卡**：真人/卡通形象口型 + 字幕 + 语音；数字人 Agent 多轮对话（若道模型/外部 OpenAI/FAQ/知识库回退），支持一对多直播、一对一排队、一对多轮流接待 |
| 本地开源 | still（默认）/ local（协议对接本地口型服务）/ cloud（预留） |

## 二、三步开播（网页直播 / OBS / 直播伴侣）

1. **选类型 + 上传形象**：左栏先选“真人形象”或“卡通 / 二次元”，再上传照片（PNG/JPG/WebP，≥720×1080，透明底 PNG 最佳）。
2. **写话术**：底部每行一句，打开“自动轮播”设间隔；右栏可调名字、声音、动作、口型、颜色。
3. **一键开播**：点右上“一键开播”，复制舞台地址，粘到直播伴侣“浏览器”源或 OBS“浏览器”源，尺寸 1080×1920。首次打开点一下“启用声音”。

---

## 三、推流到直播平台（RTMP / SRT）

右栏“推流到直播平台”：

1. 选平台（只是标签，地址仍用你在平台后台拿到的推流地址）。
2. 填 **推流地址**（如 `rtmp://...` 或 `srt://...`）和 **推流密钥**（有的平台拼在地址里，可留空）。
3. 选帧率、分辨率、是否带语音，点“开始推流”。

插件用本机 ffmpeg 把“形象照片 + 语音”合成 1080×1920 视频推到该地址，画面为纯人像（不带网页上的字幕/跑马灯）。要推“带完整字幕和动效的舞台”，用上面的**浏览器源**方式（OBS 虚拟摄像头）更完整，这是行业标准做法。

> ffmpeg 已随若道桌面端内置；若换机器没有 ffmpeg，推流会提示，浏览器源不受影响。

## 四、网页接待组件 · 数字人 Agent（真人 / 卡通数字人接待）

**v0.8 数字人 Agent**：接待不再只是关键词匹配，而是一个能接入若道模型、可对话的 Agent。访客打开接待卡即可**打字或语音提问**，数字人用当前音色语音播报并显示字幕。三种接待模式（右栏「接待模式」切换）：

| 模式 | 适用场景 | 行为 |
|---|---|---|
| 一对多直播 live | 直播 / 公开答疑 | 所有访客都能发言，回答并发生成、各自收到 |
| 一对一独占 solo | 私密接待 / 单独咨询 | 同一时刻只接待 1 人，其余访客排队并显示「前面还有 N 位」；当前访客结束接待或空闲超时后，自动接待下一位 |
| 一对多轮流 round-robin | 多位访客轮流答疑 | 在同时接待上限内，按到达顺序轮流回答，每人一次，回答串行不互相打断 |

回答链：高置信 FAQ → **若道宿主模型（开启「接入若道模型」且已配置文本模型）** → 外部 OpenAI 兼容接口 → 知识库检索 → 兜底话术。任一步不可用会自动降级，不会让访客卡住。

右栏“网页接待组件”：

1. 填标题、欢迎语，以及问答库（每行一条 `问题|答案`）。
2. 点“复制嵌入代码”，得到一行：
   ```html
   <script src="http://127.0.0.1:<端口>/embed.js?token=<令牌>"></script>
   ```
3. 粘到公司官网 / 个人博客 / 产品页 `</body>` 前即可。页面右下角出现 💬 浮窗，点开就是**数字人在接待**：上方是当前选中的真人/卡通形象（会呼吸，回答时张嘴说话），下方是对话。访客提问 → 命中问答 → 数字人用当前音色语音播报并显示字幕，像真人客服一样接待。

**接待增强（v0.4）**
- 快捷问题：问答库前 3 条自动变成底部快捷提问气泡，点击直接提问。
- 问候语音：打开接待点「开始接待」后，会用当前音色播报问候语。
- 知识库检索：右栏可填「知识库」（每行一条产品/政策/说明），没写进问答库的问题会先从知识库检索再作答；开启大模型时，检索结果会作为上下文一起给模型。
- 多轮对话 + 可选大模型：右栏可开启「大模型回答」，填 OpenAI 兼容接口地址 / 模型名 / API Key（只存本机）。启用后接待走大模型（带多轮上下文），未配置或调用失败自动回退问答库。

> 组件默认只监听 127.0.0.1，适合“本机演示 / 内网部署”。要公网访问，请把服务放到公网服务器并配好域名与令牌。

## 五、形象类型与动作

- **真人**：默认“稳重”曲线，呼吸/微摆/点头都很克制，接近真人坐播。
- **卡通 / 二次元**：默认“活泼”曲线，动作幅度更大、有说话起伏，适合虚拟主播。
- **抠图**：透明底卡通图可开“抠图”，舞台换成主题色渐变背景，人物更干净。
- 动作风格还可手动切“稳重克制 / 活泼夸张”，口型强度和动作幅度都能拉。

## 六、真实感升级路线：怎么做到真人级口型与表情

先说清楚现状的边界：默认 `still` 引擎是**音频频谱驱动**——用音量/频段能量拉伸照片的嘴部区域，属于"近似口型"，近景特写能看出差别。要做到**真人级**（精确口型、表情、微动作），必须换成"生成式"方案。三条路线，按成本从低到高：

### 6.1 路线 A：本地开源引擎（免费，需 NVIDIA 显卡）

**推荐 LiveTalking**（github.com/lipku/LiveTalking）：实时级、自带 WebRTC/RTMP 推流，支持多后端口型模型，是当前最完整的开源实时数字人方案。

```powershell
# 1. 预检显卡（需要 6GB+ 显存，NVIDIA + CUDA）
powershell -ExecutionPolicy Bypass -File scripts/install-engine.ps1

# 2. 部署 LiveTalking（conda 环境）
git clone https://github.com/lipku/LiveTalking.git
cd LiveTalking && conda create -n livetalking python=3.10 -y && conda activate livetalking
pip install -r requirements.txt

# 3. 下载 MuseTalk 权重后启动（对外暴露插件协议端口）
python app.py --model musetalk --transport virtualcam   # 或 rtmp / webrtc
```

启动后插件端无需改代码：右栏「引擎」选 **本地开源口型**，填 `http://127.0.0.1:8090` 点「探测」，插件按下面的协议对接：

```
GET  /health                        -> { ok, engine, gpu, fps, avatarReady }
POST /avatar   { image }            -> { avatarId }
POST /say      { avatarId, audio }  -> { jobId }        # audio 是 TTS 合成的 wav
GET  /stream?avatarId=...           -> MJPEG 逐帧流（1080×1920）
POST /reset    {}
```

其他可选本地模型（协议一样，只换后端）：

| 模型 | 显存 | 特点 |
|---|---|---|
| Wav2Lip | ≈2GB | 最稳最轻，口型清晰度一般，6GB 显卡首选 |
| MuseTalk | 8GB+（6GB 可 fp16） | 25-30fps，口型质量好 |
| Ultralight-Digital-Human | 2GB | 极轻量，实时，效果入门级 |
| LivePortrait | 6-8GB | 表情迁移强（照片会"做表情"），口型弱于 MuseTalk |

### 6.2 路线 B：云端数字人 API（无显卡，效果最好，按量付费）

照片上传后由平台实时生成精确口型 + 表情，插件侧只需要把 TTS 音频/文本发给平台、拉回视频流。

| 平台 | 关键接口 | 实时性 | 适合 |
|---|---|---|---|
| **HeyGen**（海外） | `POST /v1/streaming.create_token` → `POST /v1/streaming.new`（photo_avatar 上传照片）→ WebSocket 发 `talk` 指令 → WebRTC 拉流 | 实时交互 | 直播 / 网页接待，效果业界标杆 |
| **D-ID**（海外） | `POST /api/talks`（source_url + script）返回流；`/streams` 做 WebRTC 实时会话 | 实时 | 同上，按量计费简单 |
| **腾讯云智影** | 数字人视频合成 API（提交照片 + 音频 → 云端合成视频）；直播用智影平台 | 准实时/离线 | 国内合规、视频号场景 |
| **阿里云百炼** | DashScope `EMO`（照片 + 音频 → 表演视频，audio-driven 全身表情）；阿里云虚拟数字人做实时 | EMO 离线 / 虚拟人实时 | 表现力最强，EMO 适合短视频 |
| **火山引擎智能创作** | 数字人形象生成 + 直播互动 API | 实时 | 抖音生态顺滑 |
| **讯飞虚拟人 / 硅基智能 Duix** | 形象克隆 + TTS + 实时流 SDK | 实时 | 国内一站式，含语音克隆 |

**通用接入流程**（以 HeyGen 为例，其余同理）：

1. 平台注册拿 API Key，`POST /v1/streaming.new` 上传照片生成 `avatar_id`（一次性）。
2. 插件把话术文本（或先经 edge-tts 合成音频）通过 WebSocket 发给平台，指定音色。
3. 平台实时返回 WebRTC/FLV 视频流：直播场景把流接到 OBS/直播伴侣；接待场景接到 `widget.html` 的 `<video>`。
4. 插件预留 `engine = "cloud"` 档位，新增云端 Provider 适配层即可接入，UI 已留出扩展位。

### 6.3 要"精确"，技术上差在哪

| 环节 | 现状（still） | 真人级做法 |
|---|---|---|
| 口型 | 音频频谱能量拉伸嘴部区域 | **音素级 viseme 驱动**：edge-tts 提供 word boundary 时间戳，映射到口型参数（A/E/I/O/U + 闭唇音），逐帧对齐；或直接用生成式模型 |
| 嘴眼定位 | 手动滑条微调 | MediaPipe FaceMesh（468 个关键点）自动检测，`/avatar` 注册时算好 clip 区域，滑条只做兜底 |
| 表情 | 只有眨眼 | LivePortrait / EMO 这类表情迁移或生成模型，照片会挑眉、微笑、转头 |
| 头部微动作 | 正弦曲线 | 需要生成式模型或 3D 头部姿态估计 |

### 6.4 建议路线图

1. **短期（无新依赖）**：edge-tts 音素时间戳 + FaceMesh 自动对齐，把 still 引擎的口型对齐精度提一档。
2. **中期**：落地路线 A——一键脚本部署 LiveTalking（MuseTalk 后端），插件协议已就绪。
3. **长期**：云端 Provider 适配层（HeyGen / D-ID / 国内大厂），按用户是否有显卡/预算自动推荐档位。

```
plugins/digital-human-live/
├─ bin/live-studio.mjs     常驻服务：HTTP、runtime.json、宿主 RPC
├─ lib/
│  ├─ store.mjs            形象库（含真人/卡通类型）、配置持久化

│  ├─ widget.mjs           FAQ / 知识库语义匹配
│  ├─ agent-session.mjs    数字人 Agent 会话、接待队列、独占与轮流调度

│  ├─ index.html/app.mjs   工作台
│  ├─ stage.html/stage.mjs 1080×1920 舞台
│  ├─ widget.html/widget.mjs 接待浮窗

├─ scripts/install-engine.ps1

```

服务只监听 `127.0.0.1`，API 需要 `x-dh-token` 或 `?token=`；token 持久化，重启地址不变；素材与语音全部本机。

## 十、已知边界

- `still` 引擎是音频频谱驱动，不是逐帧口型模型，近景特写能看出差别。
- `local` 引擎需自行部署，插件只负责协议对接与预检，不含权重。
- RTMP 直推是“纯人像 + 语音”，不含网页字幕/跑马灯；完整舞台请用浏览器源。
- 接待 Agent 默认优先走若道宿主模型；未配置模型或调用失败时按 FAQ → 知识库 → 兜底顺序降级，仍可正常接待。
- 一对一/轮流模式靠服务端会话状态维持，服务重启后排队会话需重新进入；「接入若道模型」需在宿主内打开插件并已配置文本模型。
- 未做实时 ASR（连麦/弹幕语音回复）。
